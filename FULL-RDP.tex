\section{1. Executive summary}
Glacier Water Solutions ERP v3.0 is a responsive, cloud-backed workplace for daily water factory operations. It combines simple My BillBook style billing with traceable inventory, production, quality, delivery and accounts.
The owner supplied an 8 page RDP v3.0 and asked for the complete website to be built. The earlier RDP v2.0 described a static local-first PWA on GitHub Pages. V2 remains live as a read-only archive. V3 uses a new repository and a new live URL so the archive is not overwritten.
The current build is a React, TypeScript and Vite PWA with a managed Supabase backend. Supabase provides the shared PostgreSQL database, authentication, row level security and private file storage that the RDP asked for in a Node and TypeScript REST API. The app also runs in local demo mode before cloud credentials are entered.
Cloud status as of this document: the final project URL is verified, the publishable key matches the project, the full SQL schema has been executed, and the owner reported that Admin to Cloud setup is complete. The remaining work is to confirm the owner authentication user and owner row, collect auditor approvals, reconcile v2 browser backups, complete security and restore tests, and hand over training.

\section{9. Inventory and stock control}
\begin{itemize}[leftmargin=*,itemsep=2pt,topsep=2pt]
\item Separate finished goods, raw materials, packaging, damaged, expired, QC held stock and optional locations.
\item Immutable stock ledger movements: opening, purchase receipt, production receipt, sale issue, material use, return, transfer, damage, expiry and adjustment.
\item Current stock is opening plus posted inward movements minus posted outward movements. No direct balance overwrite.
\item Physical stock count workflow: count sheet, variance, reason, approval and adjustment.
\item Batch-wise stock with manufacturing and expiry dates, QC status, reorder alerts, stock valuation and stock aging.
\item FEFO dispatch suggestion for expiry controlled stock. Override requires reason and permission.

\section{10. Manufacturing and production}
\begin{itemize}[leftmargin=*,itemsep=2pt,topsep=2pt]
\item Production plan by date, shift, product and target output.
\item Batch record includes batch number, line or shift, operator, start and end time, good output, rejected output, rework and notes.
\item BOM defines expected bottles, caps, labels, cartons and other material per case or unit.
\item Record actual consumption, variance, wastage and reason. Compare standard versus actual.
\item Posting a batch debits raw materials and credits good finished goods. Rejected output is segregated and not saleable until disposition.
\item Prevent duplicate posting. Posted batch edits require reversal and repost with approval.
\item Dashboard: planned versus actual output, yield, rejection, material variance and output by size or shift.
\item Costing distinguishes direct material, labour, electricity and utilities, rent and overhead. Estimated and actual costs are clearly labelled. Accountant approves costing policy.
\end{itemize}

\section{19. Migration from RDP v2}
\begin{itemize}[leftmargin=*,itemsep=2pt,topsep=2pt]
\item Export JSON backup from every browser or device containing business records. Export Excel and CSV registers too.
\item Keep original exports read-only in at least two separate locations. Do not clear browser data or uninstall the old PWA before validation.
\item Use staging. Inspect schema version, duplicate IDs, missing fields, dates and invoice number conflicts.
\item Import masters first, then opening balances and historical transactions in controlled sequence.
\item Reconcile invoice counts and totals, purchase totals, customer and supplier balances, stock by SKU, cash and bank against source exports.
\item Import opening stock as dated movements. Avoid double-counting with historical transactions.
\item Record source device, export time, import batch, rejected rows and mapping decisions.
\item Owner and accountant sign migration reconciliation before cutover. Keep the old local build as a read-only archive.
\end{itemize}
V2 explicitly states that data is per browser and JSON backup is the portable copy. A live GitHub Pages URL or successful asset check does not mean data is stored in a shared cloud database.

\section{21. Testing and acceptance checklist}
\begin{itemize}[leftmargin=*,itemsep=2pt,topsep=2pt]
\item Create an invoice on one device and see the same posted record on another authorized device.
\item Concurrent invoice creation cannot duplicate invoice numbers or oversell stock.
\item Auditor-approved test cases verify discount, tax inclusive and exclusive, CGST and SGST, IGST, round-off, split payments and returns.
\item Case and bottle conversion is exact and handles loose bottles without silent rounding.
\item Opening plus posted inward minus posted outward equals closing stock by SKU, location and batch.
\item Production consumption, good output, rejects and batch status reconcile.
\item Cancellation and returns reverse balances correctly and preserve original history.
\item Customer and supplier ledgers reconcile to control accounts. Cash and bank opening plus movements equals closing.
\item Staff cannot access restricted cost, profit or settings endpoints by direct API request.
\item Network retries do not double-post. Failed database transactions roll back.
\item Backup restores into clean staging and record counts and totals are checked.
\item PDF, XLSX and CSV totals match filtered screen results. A4 and 80 mm print tested.
\item Core screens work at 375 px mobile width.
\end{itemize}

\subsection{26.3 Money and stock rules}
\begin{itemize}[leftmargin=*,itemsep=2pt,topsep=2pt]
\item All money is stored as integer paise. Display uses Indian formatting.
\item GST math computes inclusive and exclusive taxes, CGST and SGST or IGST, freight, round-off and grand total.
\item Stock is never stored as a directly edited balance. Current stock is opening plus posted inward movements minus posted outward movements.
\item Posting and cancellation use stock movements, ledger entries, posting references and reversal records.
\item Negative stock is blocked on dispatch.
\item Case and bottle conversion uses exact integers: 300 ml is 30 bottles per case, 500 ml and 1000 ml are 24 bottles per case.
\end{itemize}
\subsection{26.4 FEFO, QC and costing}
\begin{itemize}[leftmargin=*,itemsep=2pt,topsep=2pt]
\item \texttt{src/lib/fefo.ts} suggests the earliest-expiry QC released batch.
\item Dispatch must select a batch. Only released batches can post. Non-FEFO-first choice needs an override reason.
\item \texttt{src/lib/costing.ts} computes standard and actual cost, variance and working P and L and balance sheet statements.
\item Costs and statements are marked as working papers until approvals are complete.
\end{itemize}
